# Дневник и доска расследования в CarXCase

Интеграция использует существующие `ClueJournal`, `ClueObject`, автоответчик, допросы и сюжетные условия `DeductionBoard`. Сцены не заменены демонстрационной локацией. Старый плоский журнал и старый обработчик выбора карточек заменены согласованными дневником и пробковой доской.

## Проверить в игре

Откройте `Assets/_Project/Scenes/MainMenu.unity` и начните новую игру либо продолжите сохранение. Для быстрой проверки можно запустить `01_FatherApartment` непосредственно в редакторе: дневник будет пустым до осмотра предметов.

- **J** — дневник; **Tab** — доска; **Esc** — закрыть вложенное окно/отменить перенос, затем закрыть интерфейс.
- Осмотрите предмет обычным игровым взаимодействием. Автоответчик нужно дослушать: запись появляется после окончания воспроизведения.
- В дневнике выберите запись → **Отделить лист для доски** → подтвердите. Щёлкните по пробке, чтобы закрепить лист.
- Тяните лист мышью; тяните фон, чтобы сдвигать доску; используйте колесо для масштаба.
- Нажмите **Красная нить**, затем две улики, или нажмите непосредственно на их кнопки. Только сюжетно подтверждённые пары открывают вывод.
- Вывод появляется и в **Заметках**, и в разделе **Выводы**. Неправильная пара не открывает подсказки.
- ПКМ по нити снимает её. **Снять лист** возвращает страницу в дневник. Уже сделанные выводы и собранные улики сохраняются.
- Двойной щелчок по листу открывает его текст. Внизу страницы можно написать собственную заметку.
- У мировой доски в участке работает прежнее взаимодействие **E**. После выполнения существующих сюжетных условий появляется **Что дальше?** и прежний выбор направления.

Для текущего сюжета действуют исходные пары из сцены участка:

| Улики | Вывод |
|---|---|
| Коробок из бара + запись автоответчика | Бар Дмитрия |
| Нетронутые ценности + запись автоответчика | Порт |
| Дверь открыли изнутри + нетронутые ценности | Отец мог знать гостя |

Поездка в порт остаётся недоступной, как задано в исходной игре. Интеграция открывает соответствующий вывод, но не создаёт отсутствующую локацию.

## Добавлять свои улики и изображения

1. На игровом предмете используйте существующий компонент **ClueObject**: уникальный `clueId`, название, описание, комментарий героя и `addToJournal`.
2. В **Journal Attachments** добавьте любые текстуры и подписи. Они используются в дневнике и на доске. Поле необязательное: без изображения отображается бумажная запись с текстом. Старые фотографии чашек и конверта не назначаются новым сюжетным уликам с другими ID.
3. Новые связи задавайте в **Deductions** существующего компонента **DeductionBoard** в сцене участка. Укажите ID двух улик, уникальный ID вывода, название и текст. Условия поездок продолжают использовать эти же ID.
4. Выполните **Tools → Investigation → Rebuild game catalog** перед проверкой в Play Mode. При сборке игры каталог обновляется автоматически из включённых игровых сцен.

Каталог: `Assets/Casebook/Resources/CarXInvestigation.asset`. Здесь можно дополнить категории, иллюстрации и подписи, назначить клавиши для новых сохранений. Каталог не означает обнаружение улик: страницы создаются только через игровое событие сбора.

Программный сбор новых улик продолжает работать через `ClueJournal.Collect(id, title, description, thought)`. Существующие допросы также передают записи через этот API. Динамические текстовые записи сохраняются даже при отсутствии их ID в исходном каталоге.

## Сохранения и архитектура

Всё состояние находится в прежнем `savegame.json` игры в `Application.persistentDataPath`: реальные улики и сюжетные флаги плюс новое поле `investigation` с прочитанными страницами, заметками, положениями листов, нитями, выводами, масштабом и сдвигом. Изменения записываются сразу. Запись заменяет файл атомарно и оставляет `.bak`.

**Продолжить** восстанавливает дневник вместе с существующим игровым прогрессом. Старые сохранения без поля `investigation` переносят найденные улики и выводы в новый дневник; доску можно разложить заново. **Новая игра** очищает оба состояния. Возврат героя в сцену по-прежнему использует существующий контрольный пункт игры.

- `Assets/Casebook/Runtime` — независимые данные, страницы дневника, перетаскивание, нити и отображение.
- `InvestigationIntegration` — связь с игровыми событиями и управлением.
- `ClueJournal` — источник найденных улик и сюжетных условий.
- `DeductionBoard` — авторские связи и переходы по сюжету; вызывает общий интерфейс.
- `GameSession` / `SaveSystem` — единое сохранение игры и расследования.
- `Assets/Casebook/Editor/InvestigationCatalogBuilder.cs` — сборка каталога без перезаписи сцен.

## Автоматическая проверка

Unity **6000.6.8f1**. `InvestigationIntegrationCheck.Run` запускает реальные сцены квартиры и участка, осматривает объекты, ждёт настоящую корутину автоответчика, проверяет связи, сюжетные условия, сохранение/загрузку и сброс новой игры. `InvestigationIntegrationCheck.Resume` проверяет загрузку в новом процессе, клавиши J/Tab и делает снимки интерфейса.

Перед запуском проверки необходимо задать переменную окружения `CARX_INVESTIGATION_TEST_SAVE` с отдельной временной папкой. Тест никогда не использует пользовательское сохранение. `Resume` запускается без `-nographics`, чтобы проверить отрисовку. Подробные результаты находятся в `result.txt` и `resume-result.txt` в выбранной папке.
