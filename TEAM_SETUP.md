# CarXCase — настройка проекта и работа в команде

Совместный Unity-проект. Репозиторий содержит текущие сцены, код, модели, текстуры,
звук, видео, освещение, исходники в `ArtSource` и настройки проекта.

Репозиторий: **https://github.com/KlimLimanski/CarXCase**. Он приватный: прежде чем
скачивать проект, необходимо принять приглашение владельца. Ниже есть подробный
порядок работы для тех, кто раньше не использовал Git.

## Что означают Git, LFS, commit, push и pull

| Название | Простыми словами |
| --- | --- |
| Git | История изменений проекта на вашем компьютере |
| GitHub | Общий сервер, куда команда отправляет изменения |
| Git LFS | Дополнение Git для моделей, текстур, видео и других больших файлов |
| Clone | Первое скачивание репозитория на свой компьютер |
| Commit | Сохранение набора изменений в локальную историю |
| Push | Отправка своих коммитов на GitHub; без push другие их не получат |
| Pull | Получение чужих коммитов с GitHub |
| Branch / ветка | Отдельная линия работы над вашей задачей |
| Pull Request / PR | Предложение перенести готовую задачу в общую ветку `main` |

Сохранить сцену в Unity, сделать commit и нажать Push — это три разных действия.
После обычного Ctrl+S изменения есть только в вашей папке.

## Подробный первый запуск на Windows

### 1. Получить доступ

Войти в свой аккаунт на [GitHub](https://github.com) и принять приглашение
`KlimLimanski/CarXCase`. Оно может прийти по электронной почте или отображаться
на [странице приглашений репозитория](https://github.com/KlimLimanski/CarXCase/invitations).
Если страница репозитория показывает 404, проверить аккаунт и принятие приглашения.
Не создавать копию репозитория в своём аккаунте: работаем с одним общим CarXCase.

### 2. Установить программы

1. [Git for Windows](https://gitforwindows.org/). В установщике оставить компонент
   **Git LFS / Large File Support** и возможность использовать Git из командной строки.
2. [GitHub Desktop](https://desktop.github.com/) — удобное приложение с кнопками вместо
   большинства команд. Войти через **File → Options → Accounts → Sign in** в тот же
   GitHub-аккаунт, которому выдали доступ. При первом запуске указать своё имя и email
   для авторства коммитов.
3. [Unity Hub](https://unity.com/download), затем редактор **6000.6.8f1**.
   Версия должна совпадать с `ProjectSettings/ProjectVersion.txt`.
4. [Blender 5.3](https://www.blender.org/download/) для исходных `.blend` внутри Assets.
   Если текущая страница предлагает другую версию, использовать
   [архив релизов Blender](https://download.blender.org/release/Blender5.3/).

После установки Git закрыть и заново открыть PowerShell. Проверить:

```powershell
git --version
git lfs version
git lfs install
```

У первых двух команд должен появиться номер версии. У третьей — сообщение об успешной
настройке. Если `git` не найден, перезапустить терминал или установить Git for Windows.
Если `git lfs` не найден, установить [Git LFS](https://git-lfs.com/) и повторить команды.

### 3. Скачать CarXCase

1. В GitHub Desktop выбрать **File → Clone repository → URL**.
2. Вставить `https://github.com/KlimLimanski/CarXCase.git`.
3. В **Local path** выбрать новую папку, например `C:\UnityProjects\CarXCase`.
   Это будет ваша рабочая копия. Не клонировать в папку с другим Unity-проектом.
4. Нажать **Clone** и дождаться завершения. Ассеты большие, первое скачивание может
   занять время. LFS скачивает настоящие файлы моделей и текстур автоматически.
5. В Desktop выбрать **Repository → Open in PowerShell**. Если выбран другой терминал,
   можно открыть PowerShell в папке CarXCase самостоятельно. Выполнить:

```powershell
git lfs pull
powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\Setup-Team.ps1
```

`git lfs pull` догружает большие файлы. Скрипт настраивает Git LFS, получение обновлений
и Unity Smart Merge для этого клона. Если Unity ещё не установлен или установлен в
нестандартную папку, настройку Smart Merge можно повторить после установки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\Setup-Team.ps1 -UnityEditorPath "D:\Unity\6000.6.8f1\Editor\Unity.exe"
```

### 4. Открыть игру

1. В Unity Hub нажать **Add / Add project from disk** и выбрать скачанную папку,
   в которой находятся `Assets`, `Packages` и `ProjectSettings`.
2. Открыть её редактором **6000.6.8f1**. Если Unity предлагает сменить версию,
   сначала установить нужную через Hub.
3. Дождаться окончания импорта и загрузки пакетов. В первый раз Unity создаёт кэш
   `Library` самостоятельно. Для этого нужен интернет и свободное место на диске.
4. В окне Project открыть `Assets/_Project/Scenes/00_MainMenu.unity`, затем нажать Play.
5. Для работы над баром открыть `02_Bar.unity`: WASD — движение, мышь — обзор,
   E рядом с Дмитрием — разговор, J — журнал.

Открывать нужно корень CarXCase. В папке Arts есть исходные материалы и вложенные
файлы старых Unity-проектов; они не являются главным проектом команды.

## Как работать каждый день через GitHub Desktop

### Перед началом новой задачи

1. Убедиться, что предыдущая работа сохранена и отправлена. Закрыть Unity.
2. В Desktop выбрать CarXCase, затем **Current branch → main**.
3. Нажать **Fetch origin**. Если появилась **Pull origin**, нажать её и дождаться
   получения изменений. Fetch только проверяет сервер; Pull переносит обновления к вам.
4. Нажать **Current branch → New branch**, назвать ветку по задаче, например
   `feature/churlik-bar-clues`, и создать её от актуальной `main`.
5. Открыть проект в Unity и работать в своей ветке.

Ветка `main` — общее рабочее состояние. Новые задачи делаем в отдельных ветках.
Сначала договориться, кто меняет бар, кто ломбард и кто код: разные ветки не устраняют
конфликт, если двое одновременно переставляют одни и те же объекты одной сцены.

### Как сохранить и отправить свою работу

1. В Unity нажать Ctrl+S, сохранить изменённые сцены и prefab, затем закрыть Unity.
2. Открыть **Changes** в Desktop. Проверить список: там должны быть ваши сцены,
   скрипты, ассеты и связанные `.meta`, а не посторонние изменения.
3. В поле **Summary** написать, что сделано, например «Добавить улики на столы бара».
   При необходимости заполнить **Description**.
4. Нажать **Commit to …**. Теперь изменения записаны локально.
5. Нажать **Publish branch** при первой отправке ветки, затем **Push origin** при
   следующих отправках. Дождаться завершения загрузки, включая большие LFS-файлы.
6. Если задача ещё не готова, продолжать в этой ветке и повторять commit + push.
   Небольшие законченные изменения удобно сохранять отдельными коммитами.

### Как передать готовую задачу в общий проект

1. После push нажать **Create Pull Request** в Desktop.
2. В браузере проверить: **base: main**, **compare: ваша ветка**.
3. Описать результат и способ проверки: какую сцену открыть, какие кнопки нажать,
   что должно произойти. Для визуальных изменений приложить скриншот.
4. Создать Pull Request и передать его владельцу проекта на проверку.
5. После проверки владелец объединяет PR кнопкой **Merge**. Если GitHub сообщает
   о конфликтах, сначала совместно разрешить их, затем проверить проект в Unity.
6. Остальные закрывают Unity, переключаются на `main`, нажимают Fetch, затем Pull.
   После этого у них появятся ваши изменения.

Отправленная ветка ещё не меняет чужую `main`: общий проект обновляется после Merge.
Если задача длится долго, согласовать получение новых изменений `main` в свою ветку.

## Модели, сцены и конфликты

- Новые модели, текстуры и аудио помещать в `Assets/_Project/Arts` в подходящую папку.
  Дождаться импорта Unity: она создаст `.meta`. Коммитить оба файла вместе.
- Перемещать и переименовывать ассеты через окно Project в Unity. GUID из `.meta`
  связывает сцену с моделью, материалом или скриптом; его нельзя произвольно менять.
- Для `.blend`, `.fbx`, `.glb`, изображений, аудио и видео LFS уже настроен.
  Ничего вручную в GitHub для каждого файла добавлять не нужно.
- Одну Blender-модель одновременно редактирует один человек. Git не может
  автоматически объединить две независимо изменённые бинарные модели.
- Перед изменением одной сцены несколькими людьми распределить работу или вынести
  отдельные элементы в prefab, чтобы редактировать разные файлы.
- При конфликте `.unity`, `.prefab` или `.meta` сохранить свою ветку и обратиться
  к владельцу. Не выбирать случайно «оставить моё / чужое» и не вставлять файлы
  поверх всей папки проекта: так можно потерять чужую работу или ссылки.
- Обновления Unity и пакетов делать отдельной согласованной задачей.

## Если что-то не получается

| Проблема | Что сделать |
| --- | --- |
| Repository not found / 404 | Войти в нужный GitHub-аккаунт, принять приглашение, проверить URL |
| `git` не найден | Установить Git for Windows и заново открыть терминал |
| `git lfs` не найден | Установить Git LFS, выполнить `git lfs install` |
| Вместо модели маленький текст с `version https://git-lfs.github.com/spec/v1` | В папке проекта выполнить `git lfs pull` |
| LFS сообщает quota / bandwidth exceeded | Сообщить владельцу репозитория; это ограничение хранилища на GitHub |
| Unity не импортирует `.blend` | Установить Blender и перезапустить Unity; исходный проект использует 5.3 |
| Pull или смена ветки мешают локальные изменения | Сначала сохранить их в своей ветке, сделать commit и push; затем обновляться |
| GitHub показывает conflict | Согласовать разрешение с владельцем проекта |
| Unity долго импортирует после Clone | Дождаться первого импорта; `Library` не скачивается из репозитория |

История коммитов видна во вкладке **History** в GitHub Desktop. По ней можно понять,
кто и что менял. Если что-то сломалось, сообщить владельцу название своей ветки,
последний коммит и текст ошибки из Unity Console.

## Краткий запуск через командную строку

1. Получить доступ к приватному репозиторию у владельца и принять приглашение GitHub.
2. Установить Git с Git LFS и Unity Hub.
3. Через Unity Hub установить **Unity 6000.6.8f1**. Версия также указана в
   `ProjectSettings/ProjectVersion.txt`. Для исходных `.blend` в `Assets` нужен
   установленный Blender; на исходном компьютере используется Blender **5.3**.
4. Скачать проект через Git, затем выполнить настройку:

   ```powershell
   git lfs install
   git clone https://github.com/KlimLimanski/CarXCase.git
   cd CarXCase
   git lfs pull
   powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\Setup-Team.ps1
   ```

5. В Unity Hub выбрать **Add / Add project from disk**, указать папку `CarXCase`
   и открыть её редактором 6000.6.8f1. Дождаться загрузки пакетов и импорта ассетов.
   Первый импорт дольше последующих запусков.
6. Открыть `Assets/_Project/Scenes/00_MainMenu.unity` и нажать Play.

GitHub Desktop также подходит: клонировать репозиторий через него, затем запустить
`Tools/Setup-Team.ps1` из скачанной папки. Обычный Download ZIP не является рабочей
копией Git; используйте Clone для совместной работы и получения LFS-ассетов.

Unity создаст `Library`, `Temp`, `Logs` и `UserSettings` на каждом компьютере.
Эти папки, локальные скриншоты и временные резервные копии в Git не загружаются.
Копирование `Library` с другого компьютера не требуется.

## Ежедневная работа

Перед обновлением или переключением ветки сохранить работу и закрыть Unity.
Для каждой задачи создавать отдельную ветку, например:

```powershell
git switch main
git pull --ff-only
git lfs pull
git switch -c feature/bar-investigation
# Открыть Unity, внести изменения, сохранить сцены и закрыть Unity.
git status
git add Assets Packages ProjectSettings
git commit -m "Добавить взаимодействия в баре"
git push -u origin feature/bar-investigation
```

После push открыть Pull Request в `main`, проверить изменения с другим участником
и объединить. Остальные получают обновления через `git pull --ff-only` и `git lfs pull`.
При незакоммиченных изменениях сначала завершить свою работу; не выполнять reset
или перезапись файлов только для того, чтобы заработал pull.

- Договориться, кто редактирует каждую сцену: одновременно менять один `.unity`
  нескольким людям сложно. Выносить самостоятельные объекты в отдельные prefab.
- Всегда коммитить ассеты вместе с `.meta`. Перемещать и переименовывать их через
  Unity Project, чтобы сохранялись GUID и ссылки.
- Все используют одну версию Unity. Обновление редактора и пакетов делать отдельной
  согласованной задачей.
- Большие бинарные файлы хранятся через Git LFS. Для одновременного редактирования
  одной Blender-модели согласовать владельца задачи; бинарные модели не объединяются
  автоматически.
- Если вместо модели виден небольшой текст с `version https://git-lfs.github.com/spec/v1`,
  выполнить `git lfs install` и `git lfs pull`.

`Tools/Setup-Team.ps1` настраивает LFS и Unity Smart Merge для локального клона.
Настройки Unity уже используют **Visible Meta Files** и **Force Text**.

## Пакеты и дополнительные инструменты

Пакеты Unity восстанавливаются из `Packages/manifest.json` и `packages-lock.json`.
Пакет `com.coplaydev.unity-mcp` включён в репозиторий вместе с лицензией,
поэтому не требует папки Downloads с компьютера автора. Подключение AI/MCP-сервера
каждый участник настраивает у себя; для обычной работы над игрой оно не нужно.

Документация: [Git LFS и совместная работа](https://docs.github.com/en/repositories/working-with-files/managing-large-files/collaboration-with-git-large-file-storage),
[приглашение участников](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository).
